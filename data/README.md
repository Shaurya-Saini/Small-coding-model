# data/ — dataset preparation

Scripts are kept **deliberately separate** so training and evaluation data can
never mix (CLAUDE.md rule #2).

| Script | Dataset | Purpose | Feeds training? |
|---|---|---|---|
| `prepare_reasoning_traces.py` | `nvidia/OpenCodeReasoning` (`split_0`) | **v2** SFT corpus: R1 reasoning traces → `data/reasoning_train.jsonl` | **Yes (v2)** |
| `prepare_apps.py` | `codeparrot/apps` (**train** split) | **v1** SFT corpus: golfed prompt→solution pairs | Yes (v1, superseded) |
| `prepare_livecodebench.py` | `livecodebench/code_generation_lite` | Download + manifest only | **Never** |

The APPS **test** split is intentionally *not* processed here — it is held out for
the internal eval (generated by bigcode-evaluation-harness, scored by
`eval/score_apps.py`).

## v2 — reasoning traces (current)

`prepare_reasoning_traces.py` streams OpenCodeReasoning `split_0` and writes a
firewalled subset of DeepSeek-R1 reasoning traces. Each output row is
`{id, source, difficulty, prompt, response, n_tokens}`, where `response` is
`<think> reasoning </think>` followed by a single fenced Python solution. Training
computes loss on `response` (reasoning **and** code); the prompt is masked.

**Firewall (two mandatory filters, see the script header):**
1. `split == "train"` — drops every APPS-test / TACO-test / `*-valid` problem.
2. `dataset ∈ {apps, taco, code_contests, codeforces}` — the `ALLOWED_SOURCES`
   constant. Edit that one constant to change the policy.

> **LiveCodeBench caveat (Phase 3):** `codeforces`/`code_contests` train problems
> can overlap LiveCodeBench's recent window. The APPS firewall is airtight here;
> the LCB firewall is enforced at eval time by pinning the LCB version window to
> dates that post-date this corpus (or decontaminating LCB by problem id).

```bash
pip install -r ../requirements/data.txt

# Full v2 corpus: ~10k examples, each ≤ 8192 tokens (matches training)
python prepare_reasoning_traces.py                 # -> data/reasoning_train.jsonl

# Quick smoke (few hundred rows, shorter cap; no tokenizer download)
python prepare_reasoning_traces.py --target 200 --max-seq-len 4096 --no-token-filter
```

Key flags: `--target` (subset size), `--max-seq-len` (token cap, default 8192),
`--per-source-frac` (per-source cap, default 0.4), `--no-token-filter` (use a
char-length proxy instead of loading the Qwen tokenizer).
